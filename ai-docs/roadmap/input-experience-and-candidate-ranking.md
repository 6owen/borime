# 输入体验与候选排序路线图

状态：执行中
更新时间：2026-08-26

## 1. 当前决策

本阶段继续以雾凇拼音（rime-ice）作为中文方案和词库基础，不接入万象。雾凇与万象是两套
不同的方案生态，并不是给同一个模型简单追加词表；在刷新稳定性和个人词频仍未处理好时切换
方案，会同时改变词库、模型和调试基线，难以判断体验变化来自哪里。

以下约束已经确定：

- AI 翻译完成后必须立即刷新当前候选窗，不能要求用户继续输入或增删编码。
- 刷新不能打断用户已经移动到的页码和候选位置。
- AI 只增强候选注释，不参与中文候选排序。
- 常用词排序先依靠雾凇基础词频、Rime userdb 的个人学习和可选语言模型优化。
- 万象不在当前里程碑范围内；以后若评估，作为独立方案迁移进行对比测试。

## 2. 已完成

### M0：快捷键冲突

- 从方案菜单快捷键中移除 `Control+grave`。
- 保留 `F4` 和 `Control+Shift+grave`，让 VS Code 的 `Control+\`` 可以正常打开终端。

### M1：恢复立即刷新

- 撤回“翻译只在下一次正常候选重算时显示”的实现。
- AI 缓存写入后继续请求 Squirrel 立即重算当前 composition。
- 恢复 `candidate_refresh_requested` / `candidate_refresh_failed` 诊断语义。

### M2：刷新时保存候选位置

- 新增独立的 `selection_keeper.lua`，在当前 librime session 内保存选择快照。
- 修正真实方向键路径：`Highlight()` 不发 `select_notifier`，改为委托原生 selector 后保存其结果。
- 保存原始编码、caret、候选绝对索引和候选正文。
- 同一 composition 重算后通过 `context:highlight(index)` 恢复原位置。
- 输入、caret 或候选正文变化时放弃恢复，避免误选。
- commit、候选删除、composition 关闭和组件销毁时清理状态。
- 已加入跨页、连续刷新、迟到刷新、候选换位和生命周期回归测试。

## 3. 下一阶段

### M3：真实交互稳定性验证

实现已经保存以下状态：

```text
当前原始编码 + 光标位置 + 候选绝对索引 + 候选正文
```

组件位于 librime 进程内，在 schema 原生 selector 之前委托一个同配置的原生 selector 处理
导航键，再保存活动 segment 的 `selected_index`；通过 `update_notifier` 在同一编码重算完成后
调用 `context:highlight(index)`。绝对索引已经包含页码信息，不需要单独维护一个可能失配的
页码状态。

只有保存的 index 仍对应相同候选正文时才恢复。输入已经变化、composition 已结束、候选数量
不足或候选顺序变化时，不恢复旧位置。

详细状态机、竞态处理和验收用例见
[`../spec/candidate-selection-preserving-ai-refresh.md`](../spec/candidate-selection-preserving-ai-refresh.md)。

需要覆盖以下真实交互：

- `Down` / `Up` 后 AI 返回。
- `Page_Down` / `Page_Up` 后 AI 返回。
- AI 返回前继续输入、退格或移动编码光标。
- 多个候选翻译先后完成，候选窗连续刷新。
- 当前候选恰好因重算消失或换位。
- composition 已提交或取消后，迟到的翻译返回。

完成自动化测试后，再在 VS Code、浏览器和普通文本框中手工验收。

### M4：候选排序基线优化

刷新问题稳定后，再独立评估“常用候选靠后”：

1. 检查雾凇词库是否完整部署，以及当前使用的确实是 `double_pinyin_flypy`。
2. 检查 userdb 是否正常写入、同步和学习，而不是只观察单次候选顺序。
3. 建立一组常用短语的固定输入样本，记录首选命中率和翻页次数。
4. 对少量强偏好词使用项目现有的固定候选配置，不大面积硬编码词频。
5. 在同一套样本上评估雾凇可选语言模型，确认收益后再决定是否默认安装。

AI 英文注释不改变这个排序基线，避免把“翻译展示”和“中文选词”耦合成同一个问题。

## 4. 暂不执行

- 不接入或混合万象词库、语法模型与方案文件。
- 不用延迟刷新换取高亮稳定。
- 不让 Node.js sidecar 猜测用户当前选中了第几个候选；它不持有 Squirrel 的活动 librime session。
- 不用 AI 返回结果重排中文候选。

## 5. 完成标准

- 新 AI 翻译无需额外按键即可出现在当前候选窗。
- 用户移动候选后，所有由 AI 缓存触发的刷新都保持同一候选高亮。
- 输入变化或候选身份变化时绝不恢复到错误候选。
- 刷新逻辑不阻塞 Rime 按键线程，模型失败不影响中文输入。
- 常用词排序优化有可重复的样本和前后数据，而不是只凭个别输入判断。
